# HR departments and received requests

- Departments: `/admin/hr/departments/management`. Uses the Groups Management presentation: searchable table, structure-type filter, supervisor names, staff counts and a View panel with staff workspace links. Only approved organisation structures (state 3) in the current organisation are listed. Structure/type configuration links to its canonical organisation settings screens; supervisor changes link to the approval-backed HR supervisor page.
- Requests: `/admin/hr/requests/received`. Defaults to all accessible received requests, newest application date first with request ID as a stable tie-break. Request Type groups remain available as filters, with total and processing counts, reference/staff/type search, every configured status plus processing/final groups, inclusive Maldives-date filters and 25-row pagination across all types or a selected type. Group counts use the complete filtered result, not just the visible page.
- Super Administrators and users with effective `Admin` or `Requests.View` permission can view organisation-wide requests. Other staff see only workflow-assigned requests or requests delivered to their notification inbox. All queries remain restricted to the current organisation; global authority does not silently switch tenant context.
- Request links use the existing domain pages and approval actions. Unsafe external/protocol-relative URLs are excluded; missing detail pages show an accurate unavailable state. No generic approval writer is introduced.
- No new database tables or columns. Uses existing Requests, RequestTypes, RequestStates, WF_ assignments, RN_RequestNotifications, organisation structures, jobs and team memberships.

Filters apply together automatically: status/date changes reload immediately, search typing is debounced by 300 ms, and Reset clears text, status, dates, request type and page. Superseded requests are canceled and stale responses discarded. Filter inputs stay enabled while results update.
